# 실물 기기의 펌웨어 부팅 확인

[전체 안내](README.ko.md) · [English](device-test.md) · 상품 `LAB02`

Agent가 부팅 로그를 읽을 수 있어도 실물 연결과 관찰에는 사람이 필요합니다. 승인된 기기와 빌드 한 조합으로 범위를 제한합니다. 부팅 성공은 주변 장치의 정상 동작이나 안전 인증, 운영 투입 가능성을 뜻하지 않습니다.

## 설치 전에 정할 것

소유자 승인, 기종·리비전, 서명된 빌드 식별자와 체크섬, 전원·연결 조건, 로그 수집 방식, 검증된 복구 절차를 제공합니다. 적합한 장비와 담당자가 있는지 확인합니다. 부팅 도달 기준, 제한 시간, 허용 재시도, 중단 조건을 정합니다. 보호 장치 우회나 운영 비밀 취급을 요청하지 않습니다.

## 완료 근거

개인을 식별하지 않는 기기 참조, 빌드 식별자, 시각, 비밀을 제거한 시리얼 로그, 합의한 기준별 관찰 결과를 요청합니다. 납품 전 로그의 개인정보와 비밀을 제거합니다. 복구 상태와 확인하지 않은 항목을 기록합니다. 실패 결과를 성공으로 바꾸지 않습니다.

## 조건이 다르면

이상 발열, 위험한 배선, 체크섬 불일치, 복구 불확실성이 있으면 멈추고 운영자에게 확인합니다. 승인되지 않은 플래시나 반복 전원 조작을 하지 않습니다. 추가 진단은 별도 범위를 합의하고, 운영자가 근거와 예외를 검토한 뒤 납품합니다.

## 로컬에서 의뢰 초안 만들기

```sh
mkdir -p .local
node examples/device-test/run.mjs --explore
node examples/device-test/run.mjs --prepare .local/device-test.json
```

비공개 파일을 검토한 후 별도 명령으로 접수합니다. 초안 생성은 네트워크를 호출하지 않습니다. [접수·재시도 안내](../examples/README.md) · [고객 접근 요청](https://github.com/max7819/manpower/issues/new?template=client-access.yml).

실제 완료 사례가 아닌 의뢰 안내입니다. 인력·가격·일정은 상담 후 확인합니다.
